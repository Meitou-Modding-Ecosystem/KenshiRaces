# 永続的なブランチ ポリシーとリポジトリのオンボーディング

すべての Meitou -Modding-Ecosystem リポジトリは [中央の永続ポリシー](https://github.com/TheIvoryDisaster/GutenStructure/blob/main/docs/branch-policy.md) :

| 支店 | 要件 |
| --- | --- |
| 普通支店 | 保護されていない |
| ベータ | PR + CI を渡す ;スーパーメンテナは自己マージなどのレビューをバイパスする可能性があります |
| メイン/リリース | PR + CI に合格 + 1 つの独立したスーパー メンテナの承認;レビューバイパスなし |

GitHub Actions にはレビュー バイパスがありません。ベータ版のチーム例外はレビューにのみ適用されます。必須の PR / CI 安全性にはバイパスがありません。 CODEOWNERS では、追加の承認要件は追加されません。

GitHub テンプレートは、ブランチ ルールセット、チームの権限、環境、またはシークレットではなく、ソースをコピーします。 GutenStructure のリリース ブランチ保護の構成は、毎時 17 時に新しいパブリック組織リポジトリを検出し、見つからない場合はチーム リポジトリの書き込みアクセスを割り当て、ポリシーを適用します。新しいリポジトリをすぐに構成するには、承認された GutenStructure メンテナーにプレビューを依頼し、そのワークフローをメインのターゲット組織に適用します。保護されたマージやパブリッシュに依存する前に、これを実行してください。 Release readiness を呼び出し側 CI に保持し、実際のパス実行を確認します。一致するワークフローがない期待されたチェックは永久に待機します。

準備ができたら、レビューされた安定したソースからメイン/リリースを作成します。政策は、彼らが存在する前から彼らをターゲットにしています。このテンプレートの不変のレビュー済み中央ワークフロー ピンを維持し、PR を通じてリリース ゲートとパッケージ パブリッシャーの両方を一緒に更新します。プライベート リポジトリには、個別のプラン/保護の検証が必要です。検出によって Azure アクセスが許可されることはありません。外部プラットフォームのシークレットは作成者が所有する環境に残り、このテンプレートからコピーされることはありません。
