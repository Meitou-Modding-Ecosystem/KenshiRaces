# Каталожные номера двигателей ( RefCheck )

Мод построен на одном движке (субмодуль `engine` этого репозитория) и воспроизводится на любой версии Meitou , имеющейся у игрока. Когда в выпуске изменяется сигнатура чего-то, что вызывает мод, исходный код мода все равно может скомпилироваться, но уже собранный DLL запрашивает у игры старый член и завершается с ошибкой во время выполнения с `MissingMethodException` .

Это не гипотетически. Meitou 0.21 дал `Inventory.Add(ItemInstance)` второй необязательный параметр ( `Add(ItemInstance, bool mainShut = false)` ). Исходный код, вызывающий `bag.Add(item)` , компилируется с любой версией, но DLL , построенный на основе версии 0.20 или старше, вызывает метод с одним параметром, которого больше нет в версии 0.21. В The Wasteland Remembers сломались сувениры в игре, и исключение остановило всю систему до конца сеанса. Ни один тест не уловил этого: тесты компилируются для одного движка.

<a id="what-it-checks"></a>
## Что он проверяет

`tools/RefCheck` считывает метаданные встроенного мода DLL и перечисляет все элементы движка, на которые он ссылается (методы, конструкторы, поля типов в `Meitou*.dll` ), по имени и типам параметров, которых нет в данной версии. Ничего из мода и игры не запускается.

`tools/refcheck.sh` собирает каждый мод в репозитории (каждую папку верхнего уровня с `meitou.json` и `<Folder>/<Folder>.csproj` ), загружает zip-архив win-x64 один раз (сохраняя только `Meitou*.dll` и `0Harmony.dll` ) и проверяет каждую сборку в списках `meitou.json` мода.

```
tools/refcheck.sh                   # the newest full Meitou release
tools/refcheck.sh v0.21.0 v0.20.1   # given releases, e.g. the oldest your meitou.json allows
CACHE=<dir> tools/refcheck.sh       # where downloaded release DLLs are kept
```

Вывод, по одной строке на релиз и сборку:

```
v0.21.0 ExampleMod/ExampleMod.dll: 1 engine references checked, 0 missing
```

или на перерыв:

```
MISSING Meitou.Simulation.Items.Inventory::Add(Meitou.Simulation.Items.ItemInstance)
```

<a id="in-ci"></a>
## В CI

Задание `Engine references` запускает `tools/refcheck.sh` для проверки новейшей версии при каждом PR и отправке, а `Release readiness` ожидает его. Мод, который поставляет DLL , построенный на более старом движке, также должен проверять наличие DLL для каждой версии, которую позволяет его `meitou.json` .

<a id="when-it-finds-something"></a>
## Когда он что-то находит

Вызовите член таким образом, который работает для каждой поддерживаемой вами версии: перестройте его на более новом движке, если вы удалите старые, или найдите член путем отражения и заполните параметры, которые вы не передаете, их значениями по умолчанию. `InventoryCompat` из The Wasteland Remembers делает последнее для `Inventory.Add` .

Вызовы отражения в движке не проверяются: они мягко завершаются сбоем там, куда вы их написали.
