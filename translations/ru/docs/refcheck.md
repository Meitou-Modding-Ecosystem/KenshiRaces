# Моторные ссылки (RefCheck)

Мод построен против одного двигателя (это репо `engine` Подмодель) и играть на том, что Meitou освобождает игрока. Когда выставка изменяет подпись чего-то, то источник мода может все еще сочиняться, но DLL что уже построеные просит игру для старого члена и не успевает во время `MissingMethodException`.

Это не гипотетическое. 0 0 0 1 0 0 0 0 `Inventory.Add(ItemInstance)` Вторая часть параметров (`Add(ItemInstance, bool mainShut = false)`). Источник, который призывает `bag.Add(item)` С другой стороны, в каждой версии, но DLL Построенный против 0,20 или старше, называется метод одного параметра, который 0.21 больше не имеет. В The Wasteland вспоминают, что в игре разбиты консерваторы, а исключение осталось на всей системе. Никакого теста не зафиксировано: тесты сочетаются против одного двигателя.

<a id="what-it-checks"></a>
## Что проверяет

`tools/RefCheck` Читайте встроенный модуль DLLметаданные и перечисляет каждый двигатель, который он ссылается (методы, конструкторы, поля по типу в `Meitou*.dll`По названию и типам параметров, что данное издание не имеет. Ничего из мода или игры не работает.

`tools/refcheck.sh` сохраняет каждый режим в репо (каждая папка верхнего уровня с `meitou.json` и `<Folder>/<Folder>.csproj`Скачать Win-X64 ZIP один раз `Meitou*.dll` и `0Harmony.dll`и проверяет каждую группу мода `meitou.json` Список →

```
tools/refcheck.sh                   # the newest full Meitou release
tools/refcheck.sh v0.21.0 v0.20.1   # given releases, e.g. the oldest your meitou.json allows
CACHE=<dir> tools/refcheck.sh       # where downloaded release DLLs are kept
```

Выход, одна линия за выпуском и собрание:

```
v0.21.0 ExampleMod/ExampleMod.dll: 1 engine references checked, 0 missing
```

Или для перерыва:

```
MISSING Meitou.Simulation.Items.Inventory::Add(Meitou.Simulation.Items.ItemInstance)
```

<a id="in-ci"></a>
## В ЦИ

В том числе `Engine references` Рабочие проходят `tools/refcheck.sh` против последнего выпуска на каждом ПР и давления, и `Release readiness` Ждем на это. Мод, который бросает DLL Построенный против старого двигателя должен также проверить DLL На каждом освобождении его `meitou.json` Это позволяет.

<a id="when-it-finds-something"></a>
## Когда он найдет что-то

Назовите член таким образом, чтобы он работал на каждом выпуске, которое вы поддерживаете: восстановите новый двигатель, если вы бросите старые, или найдите член, чтобы заполнить параметры, которые вы не пропускаете с их дефектами. «Пустиня вспоминает» `InventoryCompat` Последний для `Inventory.Add`.

Рефлексные звонки в двигатель не проверяются: они мягко проходят, где вы их написали.
