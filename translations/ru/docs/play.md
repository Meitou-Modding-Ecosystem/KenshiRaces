<a id="build-and-run-locally"></a>
# Сборка и запуск локально

Сборка `Play` собирает движок и каждый мод в этом репозитории, копирует имена модов и фреймворков `meitou.lock.json` в папку модов игры, а затем запускает игру. Используйте любой инструмент, который вам нравится: Visual Studio , VS Code или терминал, все запускают одну и ту же сборку.

Всем троим нужен . NET 11 SDK и клон с его подмодулями ( `git clone --recurse-submodules <repo URL>` или `git submodule update --init --recursive` в существующем клоне). Без них сборка останавливается с помощью `MEITOU001` , называя эту команду.

<a id="visual-studio"></a>
## Visual Studio

1. Откройте репозиторий `.slnx` .
2. Установите `Play` в качестве запускаемого проекта, если Visual Studio не выбрал его (щелкните правой кнопкой мыши > Установить как запускаемый проект).
3. Выберите профиль в раскрывающемся списке рядом с кнопкой «Пуск», затем нажмите F5 (отладка) или Ctrl+F5:

| Профиль | Бежит | Используйте его для |
| --- | --- | --- |
| Играть (движок + моды) | `MeitouClient.exe` создан на основе подмодуля `engine` этого репозитория. | тестирование и отладка вашего мода; точки останова в коде мода работают |
| Лаунчер Meitou (установлен) | лаунчер установленный из релизов Meitou , `%LOCALAPPDATA%\MeitouLauncher\current\meitou-launcher.exe` | изменение списка модов или порядка загрузки и доверие к коду нового мода |

<a id="vs-code"></a>
## VS Code

1. Установите расширение C# Dev Kit ( VS Code предлагает его при открытии папки; оно находится в `.vscode/extensions.json` ).
2. Откройте корневую папку репозитория («Файл» > «Открыть папку»).
3. Запустите и отладьте (Ctrl+Shift+D), выберите **Играть (движок + моды)**, нажмите F5. Сначала он собирает и развертывает, затем запускает движок под отладчиком; точки останова в коде мода работают.
4. Для установленной программы запуска: Терминал > Запустить задачу > ** Программа запуска Meitou (установлена)**. Он собирает и развертывает, а затем открывает панель запуска.

Терминал > Запустить задачу сборки (Ctrl+Shift+B) только выполняет сборку и развертывание.

<a id="without-an-editor"></a>
## Без редактора

Щелкните правой кнопкой мыши `tools\Build.ps1` > **Выполнить с помощью PowerShell**. Он собирает и развертывает, как `dotnet build` (сначала проверяя подмодули, если они отсутствуют), и оставляет окно открытым, чтобы вы могли прочитать результат. `-Test` также проводит тесты;  Затем `-Run` запускает двигатель.

<a id="terminal"></a>
## Терминал

В корневой папке репо:

```powershell
dotnet build
dotnet test
dotnet run --project Play
```

- `dotnet build` и `dotnet test` создают и тестируют каждый проект.
- `dotnet run --project Play` собирает, разворачивает и запускает движок (профиль «Играть (движок + моды)»).
- Чтобы вместо этого использовать установленный лаунчер, разверните его, не запуская движок, затем откройте лаунчер:

```powershell
dotnet build Play
& "$env:LOCALAPPDATA\MeitouLauncher\current\meitou-launcher.exe"
```

<a id="what-a-play-build-does"></a>
## Что делает игровая сборка

- Находит моды: каждую папку верхнего уровня, содержащую `meitou.json` и `<Folder>/<Folder>.csproj` . Новый мод не требует изменений в `Play` .
- Собирает движок и каждый мод в **Release**, независимо от выбранной вами конфигурации: сборки отладочного движка добавляются в `TaskStart.CheckStarts` , как только мод запускает задачу персонажа. Точки останова в коде мода по-прежнему работают (используются символы выпуска).
- Копирует `<Mod>.dll` , `<Mod>.pdb` и `meitou.json` каждого мода в `<Kenshi>\mods\<Mod>\` . Сначала закройте игру: запущенная игра блокирует dll.
- Копирует каждый фреймворк в `meitou.lock.json` из папки загруженного выпуска в `<Kenshi>\mods\<Framework>\` или, для фреймворка, созданного из клона ([local-development.md](local-development.md) ), его выходные данные сборки.
- Мод с генератором данных ( `<Mod>.Data/<Mod>.Data.csproj` , запускаемый как `<generator> <Kenshi folder> <output .mod>` ) получает свой `<Mod>.mod` , сгенерированный из установленной игры; сбой — это предупреждение сборки, и мод развертывается без него. Любой другой мод получает пустой `<Mod>.mod` , когда его нет; существующий никогда не заменяется.
- Мод с папкой `Structures` импортирует свои модели `.glb` в развернутую папку, а записи объединяются в `.mod` ([structures.md](structures.md) ).
- Когда папка модов не существует, ничего не копируется и об этом говорит сборка.
- Кнопка «Воспроизвести» в программе запуска запускает установленную версию, а не движок этого репозитория. Закройте его и запустите «Играть (движок + моды)», чтобы протестировать свою сборку.

<a id="settings"></a>
## Настройки

По умолчанию: игра `C:\Program Files (x86)\Steam\steamapps\common\Kenshi` , папка модов `<game>\mods` . Измените их с помощью переменной среды `KENSHI_PATH` (движок тоже ее читает, поэтому оба согласны) или для каждой машины в игнорируемом git `Meitou.user.props` в корневой папке репозитория:

```xml
<Project>
  <PropertyGroup>
    <KenshiDir>D:\Games\Kenshi</KenshiDir>           <!-- game folder; also sets the mods folder -->
    <KenshiModsDir>D:\Games\Kenshi\mods</KenshiModsDir> <!-- mods folder only -->
    <PlayConfiguration>Debug</PlayConfiguration>      <!-- engine and mods configuration (default Release) -->
    <PlayDeploy>false</PlayDeploy>                    <!-- build and run without copying -->
    <PlayArguments>--continue</PlayArguments>         <!-- engine command line (Visual Studio and dotnet run) -->
  </PropertyGroup>
</Project>
```

Движок находит игру самостоятельно (Steam); `KenshiDir` , установленный только в `Meitou.user.props` , ему не передается.  Конфигурация запуска VS Code запускает механизм Release; отредактируйте `.vscode/launch.json` локально, если вы измените `PlayConfiguration` .

<a id="first-run"></a>
## Первый запуск

- Запустите установленный лаунчер один раз (любым из вышеперечисленных способов): включите мод и его фреймворки и доверьтесь его коду.
- Если копирование завершается с ошибкой «Доступ запрещен», предоставьте пользователю права на изменение `Kenshi\mods` (Свойства > Безопасность), а не запускайте редактор от имени администратора.
