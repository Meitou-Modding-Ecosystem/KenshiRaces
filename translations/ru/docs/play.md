# Строить и управлять локально

Строительство `Play` Строится двигатель и каждый модуль в этом репо, копирует модуль и рамки. `meitou.lock.json` Название в папку моде игры, а затем начинается игра. Используйте любой инструмент, который вам нравится: Visual Studio, VS Code или терминал, который выполняет одну и ту же конструкцию.

Все трое нуждаются вNET 11 SDK и уплотнение его подмодулей (`git clone --recurse-submodules <repo URL>`или `git submodule update --init --recursive` в существующем клоне). Без них строительство прекращается. `MEITOU001`Назовите это командование.

<a id="visual-studio"></a>
## Визуальные студии

1. Откройте реп `.slnx`.
2. Сеть `Play` как проект стартапа, если Visual Studio не выбрал его (право нажмите > Настройка как проект стартупа).
3. Выберите профиль в падении вниз рядом с кнопкой Начало, а затем нажмите F5 (дебаг) или Ctrl+F5:

| Профиль | РУН | Используйте его для |
| --- | --- | --- |
| Играть (мотор + модуль) | `MeitouClient.exe` Созданный из этого репо `engine` Подмодули | тестирование и дебютирование вашего мода; перерывы в работе с модом |
| Meitou Launcher (настроенный) | Издатель, установленный из Мету, выпустит `%LOCALAPPDATA%\MeitouLauncher\current\meitou-launcher.exe` | Изменение списка моде или загрузка порядка и доверие кода нового моде |

<a id="vs-code"></a>
## против кода

1. Инсталлировать расширение C# Dev Kit (VS Code предлагает, когда вы открываете папку; `.vscode/extensions.json`).
2. Откройте коренную папку репо (Файл > Открытая папка).
3. Выберите и дебютируйте (Ctrl+Shift+D) **Играть (мотор + модуль)**Пресс F5. Сначала он строит и развертывает, а затем начинает двигаться под
Дебюггер; разрывные точки в работе с модом.
4. Для установленного запускателя: Терминал > Run Task > **Meitou Launcher (настроенный)**. Он строит и развертывает, а затем открывает запускатель.

Терминал > Run Build Task (Ctrl+Shift+B) только создает и развертывает.

<a id="without-an-editor"></a>
## Без редактора

Правый клик `tools\Build.ps1` > **Используйте PowerShell**. Он строит и развертывает как `dotnet build` (Сначала проверяйте подсознания, если они отсутствуют) и держите окно открытым, чтобы вы могли прочитать результат. `-Test` также проводят тесты; `-Run` Затем начинается двигатель.

<a id="terminal"></a>
## Терминал

В коренной папке репо:

```powershell
dotnet build
dotnet test
dotnet run --project Play
```

- `dotnet build` и `dotnet test` Создание и тестирование каждого проекта.
- `dotnet run --project Play` Строится, развертывается и запускается двигатель (профиль «Play (Motor + Mods)»).
- Чтобы вместо этого использовать установленный запуск, развернуть без запуска двигателя, а затем открыть запуск:

```powershell
dotnet build Play
& "$env:LOCALAPPDATA\MeitouLauncher\current\meitou-launcher.exe"
```

<a id="what-a-play-build-does"></a>
## Какие игры создают

- Найти моды: каждый верхний уровень хостинга `meitou.json` и `<Folder>/<Folder>.csproj`. Новый режим не требует изменений `Play`.
- Строится двигатель и каждый модуль **Освобождение**, независимо от конфигурации, которую вы выбрали: дебютный двигатель строит выброс в `TaskStart.CheckStarts`
После того как моду начинается задача персонажа. Перерывные точки в мод-коде пока работают (распространяются символы освобождения).
- Копирование каждого модуля `<Mod>.dll`, `<Mod>.pdb` и `meitou.json` Для `<Kenshi>\mods\<Mod>\`. Закройте игру сначала: проходящая игра закроет длл.
- Копируйте каждую рамку в `meitou.lock.json` Из загруженного файла выхода к `<Kenshi>\mods\<Framework>\`или для создания структуры
С одной стороны, клон ([local-development.md](local-development.md)• его строительный продукт.
- Сборник с генератором данных (`<Mod>.Data/<Mod>.Data.csproj`и бегает как `<generator> <Kenshi folder> <output .mod>`И получит ее `<Mod>.mod`
генерируется из установленной игры; неудача является предупреждением о строительстве, и режим используется без него. Каждый другой модуль получает пустоту `<Mod>.mod` Если нет, то существующий никогда не заменяется.
- Мод с `Structures` Памятник получит его `.glb` Модели, введенные в его распоряжение, записываются в его `.mod`
([structures.md](structures.md)).
- Когда папка «модс» не существует, ничего не копируется, и строительство говорит так.
- Нажатый кнопка запуска начинается с выхода, который он установил, а не с двигателя этого репо. Закройте его и запустите «Играть (мотор + моды)» для тестирования вашего
и строить .

<a id="settings"></a>
## Настройки

Недостатки: Игра `C:\Program Files (x86)\Steam\steamapps\common\Kenshi`Модный пап `<game>\mods`. Изменить их с `KENSHI_PATH` окружающей среды (мотор тоже читает, так что оба согласны) или по машине `Meitou.user.props` В коренной папке репо:

```xml
<Project>
  <PropertyGroup>
    <KenshiDir>D:\Games\Kenshi</KenshiDir>           <!-- game folder; also sets the mods folder -->
    <KenshiModsDir>D:\Games\Kenshi\mods</KenshiModsDir> <!-- mods folder only -->
    <PlayConfiguration>Debug</PlayConfiguration>      <!-- engine and mods configuration (default Release) -->
    <PlayDeploy>false</PlayDeploy>                    <!-- build and run without copying -->
    <PlayArguments>--continue</PlayArguments>         <!-- engine command line (Visual Studio and dotnet run) -->
  </PropertyGroup>
</Project>
```

Двигатель найдет игру самостоятельно (Steam); `KenshiDir` Вместе с тем только в `Meitou.user.props` Не перешел к этому. Конфигурация запуска VS Code запускает двигатель Release; `.vscode/launch.json` местный, если он меняется `PlayConfiguration`.

<a id="first-run"></a>
## Первый раунд

- Выполните установленный запуск один раз (в любом из вышеупомянутых способов): включите моду и его рамки, и доверите его код.
- Если копирование не удается с «отклоненным доступом», дайте пользователю права на `Kenshi\mods` (Внутренние свойства > Безопасность) вместо того, чтобы управлять
Редактор как администратор.
