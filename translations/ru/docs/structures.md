# Импорт моделей GLB в качестве построек без FCS

Поместите модель `.glb` (Meshy, Hi3D, экспорт Blender) в папку `Structures` вашего мода, и игровая сборка превратит ее в здание, которое вы можете разместить из меню сборки: сетка Ogre, сжатые текстуры, коллизия и записи в `<Mod>.mod`. Ни FCS, ни Blender, ни установка игры для самого импорта не требуется.

<a id="quick-start"></a>
## Быстрый старт

1. Поместите модель в `<Mod>/Structures/`, например. `MyMod/Structures/watch-tower.glb`.
2. Необязательно: рядом с ним `watch-tower.json` с любыми [настройками](#settings), например.

   ```json
   { "name": "Watch Tower", "height": 6, "materials": 20, "description": "A lookout of scrap and rope." }
   ```

3. Соберите и разверните как обычно ([play.md](play.md)): Visual Studio F5, VS Code F5 или `dotnet run --project Play`. В журнале сборки отображается одна строка `Structure ...` для каждой модели.
4. В игре: меню постройки, категория `EXTERIOR` (или та, которую вы установили). При использовании `"research": "start"` по умолчанию он известен с самого начала игры, а также в существующих сохранениях (Meitou разрабатывает разблокировки из законченного исследования, которое всегда включает `_Default Start`).
5. Зафиксируйте модель, ее `.json` и `Structures/ids.json` (написаны при первом импорте). Сгенерированные файлы являются выходными данными сборки и не фиксируются.

Без игры: `dotnet run --project tools/StructureImport -- <Mod>/Structures <Kenshi>/mods/<Mod>`.

<a id="settings"></a>
## Настройки

Все необязательно (`<model>.json`, комментарии разрешены; неизвестное имя является ошибкой, поэтому опечатки не останутся незамеченными).

| Параметр | По умолчанию | Значение |
| --- | --- | --- |
| `name` | имя файла, `-` / `_` как пробелы | имя в меню сборки |
| `description` | `""` | создать текст меню |
| `height` | собственный размер модели | Готовая высота в метрах; модель масштабируется равномерно.  Модели AI имеют произвольные размеры, поэтому установите этот параметр. |
| `sink` | `0` | метров утоплены в землю (предохраняет от плавания на склонах) |
| `yaw` | `0` | градусов, повернутый вокруг вертикальной оси |
| `category` | `EXTERIOR` | категория меню сборки (`building category`): название игры (`BUILDINGS`, `CAMPING`, `FARMING`,...) или новое имя |
| `group` | `""` | `building group` : здания, разделяющие одно здание, являются вариантами одной записи. |
| `materials` | `5` | Строительные материалы это стоит |
| `buildSpeed` | `2` | `build speed mult` (палаток в игре 5, домов 1-2) |
| `research` | `start` | `start` : известно с самого начала; `none` : ничто не разблокирует его (это делают ваши собственные записи); или идентификатор строки RESEARCH, например. `96564-rebirth.mod` |
| `placement` | `outdoor` | `outdoor`, `indoor` или `both` |
| `createsTown` | `true` | размещение за пределами города запускает форпост |
| `collision` | `mesh` | `mesh` (упрощенная копия модели), `box` (ее ограничивающая рамка) или `none` (пройти сквозь нее) |
| `collisionTriangles` | `2000` | большинство треугольников, которые сохраняет столкновение `mesh` (от 12 до 50 000) |
| `textureSize` | `2048` | наибольшая сторона текстуры в пикселях (степень двойки, максимум 8192) |

<a id="item-models"></a>
## Модели предметов

Вместо этого поместите модель предмета в `<Mod>/ItemModels/` (`Structures` превратит его в здание). Импорт записывает свою сетку и текстуры рядом со структурами и одной записью MATERIAL_SPECS_CLOTHING ; запись ITEM вашего мода указывает на них. В журнале сборки отображается одна строка `Item ...` для каждой модели с используемыми именами.

1. `MyMod/ItemModels/lantern.glb`, опционально `lantern.json` : `{ "size": 0.3 }`.
2. В записи элемента (генератор данных или фаза данных) установите:

| Поле | Значение |
   | --- | --- |
| `mesh` и `ground mesh` (имена файлов) | `<mod>_<model>.mesh`, например. `mymod_lantern.mesh` | | `material` (ссылка) | `<950000 + 100 × block>-<Mod>.mod`, блок из `ItemModels/ids.json`, например. `950000-MyMod.mod` |

Сначала просмотрите материал (`GameDatabase.Find`) и сохраните внешний вид дублера, когда он отсутствует: выпущенный zip-файл и тесты, которые читают игру без развернутого мода, его не имеют.
3. Зафиксируйте модель, ее `.json` и `ItemModels/ids.json`.

| Параметр | По умолчанию | Значение |
| --- | --- | --- |
| `name` | имя файла, `-` / `_` как пробелы | название записи материала |
| `size` | собственный размер модели | самая длинная сторона в метрах; модель масштабируется равномерно |
| `yaw` | `0` | градусов, повернутый вокруг вертикальной оси |
| `textureSize` | `1024` | наибольшая сторона текстуры в пикселях (степень двойки, максимум 8192) |

- Один материал для каждой модели элемента (ITEM называет один `material`); модель стоит в самой нижней точке по центру, как это делают сетки предметов в игре.
- Игра рисует предмет на земле, в руке и на автозначке с его `mesh` (`ground mesh` первым на земле) и MATERIAL_SPECS_CLOTHING с его именем `material` (движок `docs/formats/runtime-materials.md` "Звоняки", `WorldObjectLayout.ItemMesh`).
- Значок инвентаря рисуется из модели, если только запись не устанавливает `auto icon image` false и не устанавливает собственный `icon`.

<a id="getting-a-good-model"></a>
## Приобретение хорошей модели

- Попросите у Meshy или Hi3D модель с текстурой PBR и загрузите ее как GLB. Несколько десятков тысяч треугольников вполне достаточно; в журнале отмечена модель старше 150 000. Нарезаем полиграфию, выбираем размер и уменьшаем текстуры: [model-prep.md](model-prep.md).
- Лицевая сторона модели в файле обращена к +Z (соглашение glTF); используйте `yaw`, чтобы повернуть его.
- Каждый материал становится отдельной частью. Генераторы обычно дают один; максимум 49.
- Модель стоит в самой нижней точке по центру.

<a id="what-it-writes"></a>
## Что пишет

В папку развернутого мода (`<Kenshi>/mods/<Mod>/`):

- `structures/<mod>_<model>.mesh` (по одному на материал, `_1`, `_2`,... если несколько): Ogre `[MeshSerializer_v1.8]`, положение, нормаль, UV и касательная с направлением руки в w, расположение собственных строительных сеток игры.
- `structures/<mod>_<model>_d.dds`, `_n.dds`, `_m.dds` : диффузный (BC3), нормальный (BC1, BC3 при вырезании), металличность (BC1), с мипсами.
- `structures/<mod>_<model>_col.xml` : столкновение.
- Для модели предмета: `structures/<mod>_<model>.mesh` и его текстур, коллизий нет.
- Записи объединены в `<Mod>.mod` рядом со всем остальным в нем (записи генератора данных сохраняются; более ранние импортированные записи заменяются): BUILDING, по одному BUILDING_PART и MATERIAL_SPEC на каждый материал и разблокировка (исследовательский `enable buildings` получает здание); один MATERIAL_SPECS_CLOTHING на каждую модель изделия.

Имена файлов начинаются с имени мода, потому что игра ищет ресурсы по простому имени файла в каждом моде.

Идентификаторы записей: `<n>-<Mod>.mod` с n от 900000 и выше, блоком по 100 на модель (здание +0, детали +1, материалы +50); Модели предметов считаются от 950000 (материал +0) в `ItemModels/ids.json`. `Structures/ids.json` сохраняет блок каждой модели, поэтому идентификаторы никогда не меняются: при сохранении размещенное здание именуется по идентификатору его записи. Никогда не редактируйте и не удаляйте блок; удаление модели удаляет ее здание из игр, в которых она была размещена.

<a id="facts-the-import-relies-on"></a>
## Факты, на которых основан импорт

Проверено на файлах игры (данные Kenshi 1.0.68) и ридерах движка:

- **Единицы**: мировая единица измерения — 0,1 м, Y вверх; glTF — это метры, Y вверх, поэтому масштаб равен 10 (в файлах столкновений игры используется гравитация 98,1).
- **Материалы**: внешний вид детали здания определяется ее MATERIAL_SPEC (`texture map`, `normal map`, `metalness map`, `material type`), а не именем материала сетки (движок `docs/formats/runtime-materials.md`). Строительный шейдер игры (`data/materials/deferred/objects.hlsl`) читает диффузный RGB как цвет и A как блеск (время `specular mult`), нормальный RGB как нормаль касательного пространства и A как маску выреза (`material type` 1, `alpha threshold`), металличность из R. При импорте пишет глянцевость = 1 - шероховатость glTF и металличность из синего канала glTF; glTF MASK и BLEND становятся вырезом.
- **Касательные**: бинормаль шейдера имеет вид крест(касательная, нормаль) × w, а на сетках игры она направлена ​​вдоль возрастающего V (**Проверено**: `prisoner_pole.mesh` 86 из 86 треугольников, `Camp_tent1.mesh` 1858 из 1865). Карты нормалей glTF указывают зеленым цветом вверх по изображению (уменьшая V), поэтому импорт поворачивает зеленый канал и устанавливает w в соответствии с игрой.
- **Коллизия**: `xml collision` детали является файлом PhysX NxuStream2; загружается рукописный минимальный файл (`Camp_tent1_COL.xml` игры - одна коробка). PhysX — это Z вверх, и игра отображает (x, y, z) на (x, z, -y), поэтому при импорте точки детали записываются как (x, -z, y). Треугольная сетка представлена ​​в виде простых точек и треугольников; игра готовит его при загрузке, Meitou читает как есть (движок `docs/formats/collision.md`).
- **Поля**: BUILDING и BUILDING_PART содержат полный набор полей игровой палатки Camping Tent 1 (`18026-small_changes_otto.mod`), поэтому ничего не остается по умолчанию; нет `functionality`, значит, это простое здание.
- **Разблокировка**: здание появляется в меню строительства, как только завершенное исследование указывает его в `enable buildings` ; каждая игра начинается с завершения `_Default Start` (`5359-gamedata.base`). **Проверено**с использованием движка `GameDatabase`, `ResearchGate` и `BuildingBuildData` в базовой игре, а также с импортированным модом: постройки разблокированы и стоят строительных материалов, как установлено.
