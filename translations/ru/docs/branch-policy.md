# Защита веток и подключение репозиториев

Все репозитории организации следуют единой постоянной политике. [GutenStructure](https://github.com/TheIvoryDisaster/GutenStructure/blob/main/docs/branch-policy.md)

| Ветка | Требования |
| --- | --- |
| Рабочие ветки | Без защиты. |
| `beta` | PR и успешная CI. Суперсопровождающие могут пропускать рецензию, в том числе при слиянии собственных PR. |
| `main` / `release` | PR, успешная CI и независимое одобрение одного суперсопровождающего. Обход рецензии запрещён. |

У GitHub Actions нет исключения для рецензий. На beta исключение для команды касается только рецензии. PR и обязательные проверки CI требуются всегда. CODEOWNERS не добавляет ещё одно обязательное одобрение.

Шаблоны GitHub копируют исходный код. Наборы правил, права команд, окружения и секреты настраиваются отдельно. На 17-й минуте каждого часа центральный процесс обнаруживает новые публичные репозитории, при необходимости даёт команде права записи и применяет политику. Для немедленной настройки уполномоченный сопровождающий GutenStructure (`Configure release branch protections`) запускает из main предварительный просмотр, затем применение для организации. Сделайте это до публикации и использования защищённых слияний.

Оставьте проверку Release readiness в CI вызывающего репозитория и убедитесь в наличии успешных запусков. Ожидаемая проверка без соответствующего процесса останется в ожидании. Создавайте main и release из стабильного проверенного кода. Правила назначены этим веткам ещё до их создания.

Сохраняйте проверенные неизменяемые ссылки на центральные процессы. Обновляйте через PR проверку готовности релиза и средство публикации пакетов вместе. Для частного репозитория отдельно проверьте тариф и защиту. Обнаружение репозитория не предоставляет доступ к Azure. Секреты внешних платформ остаются в окружениях их владельцев.
